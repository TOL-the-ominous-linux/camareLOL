# 更新：为什么拒绝过旧的索引

[← 文档索引](index.md)

签名能证明**是谁**签的。它对**多久以前**签的却只字不提。

这个缺口比表面看起来更重要。一个被攻破的镜像可以重放一个三个月前
的、完全有效的、签名正确的索引。关于它的一切校验都会通过——签名是真的，
校验和匹配，模式也是最新的。而一个默默接受它的客户端就此不再接收
安全修复。

光靠签名挡不住这种情况。过期机制可以。

## `expires` 字段

```json
{
  "schema": 1,
  "version": "0.1.10",
  "url": "https://…/camarelol",
  "sha256": "…",
  "expires": 1793299200
}
```

`expires` 是一个 Unix 时间戳。CI 把它设为七天之后，并按计划重新生成
索引，因此镜像始终离临界值还很远。

超过过期时间的索引，客户端会拒绝：

```console
$ camarelol --update
error: [update_rollback_blocked] the index expired
```

选择七天，是为了让镜像沉默几个小时这件事看不出来，而镜像冻结一周
则看得出来。这不是一个紧巴巴的额度——但它确实是一个额度。

## 关闭这项检查

```console
$ camarelol --update --allow-expired-index
```

这个开关是为这样的情况准备的：你的机器是气隙隔离的或只是偶尔联网，
你宁愿按自己的节奏更新。与 `--allow-unsigned-update` 一样，
它必须手动输入。

## 更旧的索引

没有 `expires` 字段的索引仍然会被接受。如果拒绝它们，那么在该字段
引入的那一刻所有客户端都会立刻失效，而最重要的恰恰是那些已经
安装好了的客户端。

这是一个有意为之的取舍：字段缺失意味着这个索引早于这项保护措施，
而不是说它是恶意的。等所有镜像都输出这个字段之后，这个例外就可以
去掉——目前保留它，是为了不让旧镜像把任何人困住。

## 镜像不会削弱信任

有人会问，增加镜像是否打开了一个缺口。并没有。

签名密钥位于二进制文件内部，既不在镜像里，也不在任何配置文件中。
一个被篡改过的镜像——改了 URL、指向别处、提供旧索引——会产生一个
客户端会拒绝的内容体。不存在能够授权任何东西的镜像。

镜像能做的是拖住你：提供陈旧内容，或者干脆不响应。这就是为什么：

- 每个索引都签名，因此无论是谁提供的，内容都会受到校验；
- `expires` 限定了"陈旧"可以陈旧到什么程度，因此镜像无法把你
  无限期地钉在某个旧版本上；
- 镜像是**按顺序**尝试的，而这份列表在构建时嵌入，因此磁盘上
  被篡改的副本无法增加或重排它们。

某个镜像宕机时会被跳过，改为尝试下一个。所有镜像全部失效意味着
无法更新——那是服务中断，不是安全攻破。
