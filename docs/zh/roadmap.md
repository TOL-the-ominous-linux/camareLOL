# 路线图

[← 文档索引](index.md)

哪些已经构建，哪些还没有，以及——在没有的地方——为什么。

## 第 1 阶段 —— MVP

已完成。

- [x] 带键盘导航和帮助的 TUI 框架
- [x] 环境检查：固件、CPU、RAM、网络
- [x] 通过 `lsblk` / `findmnt` / `blkid` 进行存储检测，并附带风险评估
- [x] 空磁盘的自动布局：GPT 和 MBR、ESP、BIOS boot、根分区、
      `/home`、swap
- [x] 文件系统选择：ext4、btrfs、xfs
- [x] locale、键盘布局、时区
- [x] 主机名、root、用户账户、带锁定防护的 sudo 策略
- [x] 最小化的 Arch 安装：pacstrap、fstab、引导加载程序、服务
- [x] 日志记录和确认界面
- [x] 安全闸门：锁定、演练（不写入）、输入短语后执行
- [x] 配置的保存与加载，带模式版本号，不含密码
- [x] 带镜像回退的签名自更新器
- [x] Python 自动化层、Java 目录、带版本号的 IPC

## 第 2 阶段 —— 桌面环境

- [ ] 桌面环境配置档：KDE、GNOME、Xfce、Cinnamon、LXQt、Hyprland、Sway
- [ ] Wayland 或 X11，通过兼容性检查来选择
- [ ] 显示管理器：SDDM、GDM、LightDM、greetd
- [ ] 驱动检测和固件建议
- [ ] PipeWire、PulseAudio，或者都不用
- [ ] 蓝牙、zram、交换空间选项
- [ ] NetworkManager 配置

## 第 4 阶段 —— 体验

- [ ] 更多界面语言
- [ ] 更好的恢复指引

## 刻意推迟的事项

其中两项之所以单独点出，是因为它们的缺失看起来像是疏忽，
而并不是。

**NTFS 调整大小。** 验收标准已经存在，安全检查也已经写好，
但这个功能并未构建。缩小一个装着某人唯一一份 Windows 副本的分区
是一个没有回头路的操作，而它应当在本项目目前能够保证的更多测试
之后才被推出。

**为双系统复用现有 ESP。** 检测与保留规则已经实现，规划代码也
知道如何不碰 Windows 分区。缺少的是布局界面，而只交付一半
意味着给某个人看一个他无法安全确认的方案。

在这两种情况下，诚实的做法是说出来，而不是提供一个做不了
它看起来该做那件事的复选框。
