# camareLOL 1.0.3 — Beta 4

**Released:** 28 October 2026  
**Status:** beta / pre-release  
**Tag:** `v1.0.3`  
**npm:** `@wenker-ai/camarelo@beta` — the `latest` tag deliberately stays on `0.1.22`

camareLOL is a safety-first TUI installer for Arch Linux. This beta fixes one
mislabelled output discovered during the 1.0.2 VM verification. Discovery,
planning, partitioning, `pacstrap`, bootloader, desktop, safety-gate, IPC and
config-schema behaviour are unchanged.

---

## 1. What went wrong in 1.0.2

### A virtio disk was labelled `kind: "SataHdd"`

The 1.0.2 release notes carried first-hand output from an Arch-in-QEMU run,
and that output contained its own confession:

```
1. devices discovered: 1
   - /dev/vda SATA HDD — 20 GiB | no partition table
```

`/dev/vda` is not a SATA drive. It is a paravirtualized virtio disk backing a
qcow2 file. The discovery JSON even said so — `transport: "virtio"` on the
same line — yet `kind` claimed SATA HDD.

The cause was an ordering bug in the kind classifier: the `rotational` flag
was consulted **before** the virtio name prefixes. Some hypervisors set
`rotational:true` on sparse images, so `vda` fell into the mechanical-SATA
bucket on its way down the decision ladder.

The misleading label was cosmetic: planning never read back the `kind` field
from the survey, and the VM run itself had PASSED. Cosmetic does not mean
harmless — an installer is judged by its output, and this output contradicted
itself inside one line.

## 2. What changed in 1.0.3

- The classifier checks the name prefixes (`vd`/`xvd`) and the `virtio`
  transport **before** the `rotational` flag. A virtio disk is `Virtual`,
  whatever the rotational bit says.
- Regression tests added: `vda` with `tran:"virtio"` and `rota:true` plus
  `xvda` both classify as `VirtualDisk`; a genuine `sda` with
  `tran:"sata"`+`rota:true` still classifies as `SATA HDD`.
